# 销货单导入当前规则及剩余事项

更新日期：2026-10-16。本文替代此前remaining_issues.md中的逐轮历史条目；讨论过程保留在discussion.md。数据库核验来源为本地UFDATA_999_1015只读结果，未执行导入或数据修改。

## 已确认规则

1. 表头SA_SaleDelivery，明细SA_SaleDelivery_b；两表ID均已核实为自增。明细idSaleDeliveryDTO绑定本次表头ID。
2. 按主表保存的源用友单号去重，先查询再导入；实际ExternalCode保存该值，ExternalVoucherCode与之同值。SourceVoucherCode在成功样本中为空，不用作源单号判重。SA code仅作为按日期递增生成的新业务编号。
3. 同一源单据任何必填关联或明细写入失败，整单不提交；其他正常单据继续。批次失败先回滚，再按完整单据拆分隔离。
4. 使用源含税金额，Decimal向零截断两位，正负同一规则；不以数量乘单价替代。
5. 制单人固定makerid=51、maker=范立志；idclerk=NULL。实际idclerk允许NULL。
6. 源客户编码匹配AA_PartnerEntity.code，取得同一id赋给idcustomer和idsettlecustomer。
7. 税率以客户档案为准：AA_PartnerEntity.taxRate关联eap_EnumItem.ID，真实税率归一为数值比例写明细taxRate。此前库存税率来源已被替代。
8. 仓库编码匹配AA_Warehouse.code，取id写明细idwarehouse；一单多仓按行匹配。
9. 项目编码匹配AA_Project.Code，取id同时写表头SA_SaleDelivery.idproject及该单全部明细SA_SaleDelivery_b.idproject；未找到项目时两处均写NULL并保留说明，不因此阻断。项目多候选或停用仍标记待处理，不任取ID。
10. 用户已确认单位使用AA_InventoryEntity.idunit关联AA_Unit.id，不解析规格末字，也不自动改用idUnitBySale。零数量退货正常插入quantity=0。
11. 目标idbusinesstype为权威业务类型：65普通销售、66销售退货；源15/16按AA_BusiType.code取得这两个ID。前缀及正负只辅助校验，不决定税率。
12. 明细idinventory关联AA_InventoryEntity.id，idunit关联AA_Unit.id；quantity与对应单位name拼成compositionQuantity（如5盒）。文本说明不替代数量换算。
13. 不生成发票和凭证；销售出库相关字段isAutoGenerateSaleOut=1、IsAutoSaleOut=1，但导入程序不调用、不执行销售出库单自动生成流程。字段标志与实际生成动作分开处理，不能仅凭标志认定已生成出库单。审核字段沿用样本：auditor=范立志、auditorid=51、voucherState=189；auditeddate使用源单据日期。按字段写入规则实施，不额外调用T+审核接口；审核流程完整性在集成验证中核实。
14. 默认配置沿用样本：idcurrency=4、idmarketingOrgan=1、iddepartment=NULL、idrdstyle=24（线上销售）；业务日期使用源单据日期，按该日期分组生成SA编号。审核业务日期也使用单据日期；createdtime/updated等系统时间记录实际操作时间，不回填样本日期。
15. 统一保留成功、重复跳过、失败、未处理等结果、原始行位置及全部原因。

## 本地数据缺口及既定校验结果

- eap_EnumItem当前0行；匹配到的7529行源客户税率ID都为351，无法按指定关联路径获得真实比例。不能猜351等于13%。
- EAP_User当前0行，无法验证固定操作员51；AA_Currency和AA_MarketingOrgan也0行，无法验证样本默认币种和组织。这是测试数据缺失，不是尚未决定税率来源或制单人来源。
- 客户40行无匹配，涉及34张单据（31种非空缺失编码及1行空客户编码），按既定规则标记不插入，不需重复询问处理政策。
- 规格末字规则已撤销；原417行匹配不到、7006行单位不同的统计不再用于当前失败判断。存货实际单位记录仍须存在且可用。
- 18种项目编码未匹配涉及1982行/1957张单据，按最新规则表头及明细项目均NULL，不算项目缺失失败。
