# 畅捷通 T+ 销货单批量导入方案

版本：2026-10-16 PyQt操作流程确认版。六步操作及本轮配置、输出、停止策略已确认；运行缺口及技术验证要求仍保留。本文替代原“按 SA code 去重”方案；业务依据为本轮用户最新确认，结构依据为 UFDATA_999_1015 的只读核验。本文是设计文档，本轮未执行导入、审核、DDL 或其他数据库修改。

## 1. 范围与执行约束

导入对象为 dbo.SA_SaleDelivery（表头）和 dbo.SA_SaleDelivery_b（明细），不是销售出库单。两表 ID 已核实为 int IDENTITY 主键，均由数据库生成；明细 idSaleDeliveryDTO 指向本次新建表头 ID。当前核验没有这两表的物理外键和触发器，业务关联仍必须由导入程序校验。

输入保持 XLS。10.12A出.xls 为真正的旧式 Excel，25列、7569条明细、5277张源单据。10万行必须读取多工作表或多文件，不能要求单个旧式XLS工作表容纳全部数据。先汇总本任务全部输入，再归集完整单据，不能按文件或读取批次拆散一张单据。

从最终判重到全部提交完成，仅一个服务串行执行一个导入任务，且无其他事务写入目标表。这是用户明确的运行前提；服务用账套级任务互斥实现自身串行，并在部署验收时核实外部写入约束。该前提改变时必须重新设计并发控制。

本次仅写销货单主明细。销售出库标志写1，但不执行自动生成销售出库单；不生成发票和凭证。审核信息按样本直接写入，不额外调用审核接口。写入审核信息与T+完整审核流程是否一致、T+后续流程是否会因销售出库标志1生成其他单据，必须在集成验证中核实，不以标志值代替业务结果。

实际客户和存货表为 Entity 表，撤销字典旧名AA_Partner/AA_Inventory作为实施查询表的写法。匹配均保留编码文本和前导零；不将数字外观编码直接当ID，不按名称、规格或别名自动回退。

项目不存在是用户明确例外：表头及全部明细 idproject均写NULL，保留源项目值和“未匹配留空”说明，单据可继续。项目多候选、停用不任取ID，按关联校验失败处理。客户、存货、单位、仓库、业务类型及税率缺失不适用项目例外。

同一源单号的日期、客户、业务类型和源项目编码必须一致；冲突标记整单失败，不取首行掩盖冲突。项目编码不同即使最终均未匹配也应保留冲突。仓库允许不一致。源XKP/XTP前缀及数量正负用于提示方向差异，不能替代业务类型档案判定，也不能据此推断税率。

## 3. 输入读取与完整单据归集

1. 检查真实文件格式、工作表、必需列；按列名建立映射，不依赖用户文件列顺序。保留文件、工作表、物理行号和原值。
2. 日期、数量、金额使用明确格式解析；编码保留文本。无效日期、空源单号、不可解析数值、超目标字段长度等累积记录，不静默截断。
3. XLS数值单元格按可验证的十进制转换策略读取，文本金额直接解析为Decimal；不得先经二进制float计算再转Decimal。源日期按工作簿日期系统解析，拒绝模糊日期。
4. 按当前账套及源用友单号归集全部明细，跨文件/工作表同号共同预检。发现重复销售标识或重复输入行时保留证据并标记输入冲突，不自动合并、删行或双计金额；具体源行身份在源文件格式验收中验证。
5. 校验单据级字段一致性。quantity=0的退货通过零数量检查，继续执行其他关联及金额检查，不做除零计算。
6. 保留输入摘要、任务ID和文件指纹，用于审计及恢复，不用文件指纹替代源单号去重。

## 4. 缓存与插入前预检

### 4.1 启动查询范围

| 类别 | 表/查询 | 范围 |
|---|---|---|
| 客户 | AA_PartnerEntity | 全量必要列：ID、编码、名称、可用状态、taxRate |
| 存货 | AA_InventoryEntity | 全量必要列：ID、编码、名称、可用状态、idunit、单计量相关属性 |
| 仓库 | AA_Warehouse | 全量必要列，按code匹配 |
| 单位 | AA_Unit | 全量必要列，按ID取名称及状态 |
| 业务类型 | AA_BusiType | 全量必要列，按code匹配 |
| 项目 | AA_Project | 全量必要列，按Code匹配 |
| 税率枚举 | eap_EnumItem | 一次批量取得客户实际引用的枚举项并缓存 |
| 固定配置 | EAP_User、AA_Currency、AA_MarketingOrgan、AA_RDStyle | 仅查51、4、1、24等本次实际引用项 |

部门固定NULL，无需加载全部部门。业务员固定NULL，无需全量人员缓存。当前命中存货均为单计量，单位组、多单位扩展不启动全量加载；遇到尚未支持的多计量商品，标记相关单据不支持，不能凭一个单位ID猜换算。无需全量加载订单、出入库、发票、凭证、银行或结算档案。

缓存按账套及任务隔离，记录加载时间和条数。最小字段建立“编码→全部候选”和“ID→记录”索引，避免重复编码覆盖；停用状态的具体字段和值按实表核验，未解释的状态不得猜测。缓存加载失败是任务级故障，不当作档案为空后批量误报。

### 4.2 校验和赋值

按用户最新操作顺序，先缓存档案并校验源数据、记录问题，再批量查询源单号重复。匹配成功后才把档案ID赋给待写对象。重复单据最终标为重复跳过，可同时保留校验发现的问题，不会因校验失败重新写入重复单据。数据库必填关系即使没有物理外键也须检查。缺失、多候选、停用、无效关联、无法解析税率等累计全部原因，任一必要条件不满足则整单不写；其他正常单据继续。

税率以客户档案为唯一来源，不回退库存税率或历史0.13。枚举ID351不是比例351，也不能猜351代表13%。枚举文本含百分号时按百分数转换；其他文本格式须由真实枚举样本建立显式解析规范，不使用“数值大于1就除100”等启发式。解析失败保留枚举ID、文本及错误原因，关联单据失败。

固定操作员、币种、营销机构存在性无法验证属于运行前置条件缺失，不默默关闭外键校验。当前本地可输出预检结果，但不得称已具备完整生产导入条件。

## 5. 源单号去重与SA编号分配

### 5.1 插入前去重

按源用友单号查询主表ExternalCode；已存在整单跳过，不覆盖、不补明细、不更新旧单。即使新文件内容变化仍按用户已确认规则跳过，保留输入摘要以便追溯。已存在记录的完整性异常另作说明，不擅自修复历史数据。

同一连接创建候选源单号临时表，列类型及排序规则与目标ExternalCode匹配，批量写入去重后的源单号，再JOIN，不拼接长IN列表、不按行查库：

```sql
SELECT p.VoucherCode, h.ID, h.code
FROM #TempPendingCodes AS p
JOIN dbo.SA_SaleDelivery AS h
  ON h.ExternalCode = p.VoucherCode;
```

不使用NOLOCK。归集及校验后批量判重；进入串行写入区后必要时再次批量判重；拆批重试和断线恢复也检查源单号。检查发现同源单号多个目标记录时保留异常ID清单并阻止再次新增。

本地目标表目前只有ID主键索引，没有源单号索引。千万级规模应评估ExternalCode索引及实际查询计划，并检查历史重复、NULL和排序规则；索引DDL是后续部署事项，本轮不执行，也不未经清洗就宣称可以加唯一索引。

### 5.2 SA编号

仅为未重复、校验通过的新单据分配：SA + 单据日期YYYYMMDD + 五位流水。按单据日期分组查询当日最大合法流水，加1；无记录从00001开始。不按最大ID、创建时间或字符串异常记录替代合法最大流水。

同日组内按文件、工作表及首次源行顺序稳定分配；跨批次不重置。同一任务内回滚重试沿用已分配编号，并重新取得自增ID；新任务重试可按数据库现状重新编号，不能因新SA号认为旧源单据未导入。允许失败形成编号空洞，不承诺无断号。超过99999或存在影响编号判断的异常格式时停止该日期组并报告，不静默扩位。插入前校验SA编号未被其他单据占用，冲突须重新核实编号状态，不能当作源单据重复。

## 6. 金额、税率与数量

### 6.1 已确认金额口径

源每行含税金额为权威金额，以Decimal统一向零截断两位：67.995→67.99，-67.995→-67.99。数量和单价不得覆盖该金额。数量保留源精度，不能套用金额两位截断。目标decimal(28,14)允许更高精度不改变本次金额规则。

明细origTaxAmount/taxAmount为含税金额字段，origDiscountAmount/discountAmount为无税金额字段，origTax/tax为税额字段；表头origTaxAmount/taxAmount及origAmount/amount分别汇总相应明细。原币与本币字段只有在汇率规则核实一致时才能同值写入；币种ID4本身不证明汇率为1。

源单价保留为原始输入及对账依据。目标含税/无税单价字段的口径、折扣及零数量场景须结合实际T+字段行为验证，不靠含税金额除零反推，也不强行修改源单价使其与截断金额相等。数量说明正确保留整数尾零，如10瓶不能变成1瓶。

### 6.2 已确认的无税金额及税额尾差算法

用户已确认以下规则：先取G=截断后的源含税金额，再以客户真实比例r计算N=向零截断(G/(1+r),2)，T=G-N；保证N+T=G，负数同样处理。例G=67.99、r=0.13，则N=60.16、T=7.83；负数分别为-60.16、-7.83。

该算法已获用户确认，正负金额统一使用Decimal向零截断（ROUND_DOWN），不使用四舍五入或向负无穷取整。税额取差额，不再独立除税重算；表头逐项汇总最终明细。原币/本币汇率、单价和其他金额辅助列的具体填充列入技术核验清单，不能在未核实情况下复制样本。

### 6.3 逐单对账

表头金额逐单汇总最终明细，不独立重算导致尾差；逐单核对行数、主明细关系、数量、含税金额、无税金额和税额，以及每行N+T=G。保留原金额、截断金额及差额。历史373行样本曾采用不同金额算法，历史121567.34合计不是本次方案必须复现的权威目标。

## 7. 批量写入与失败隔离

1. 读取配置 → 测试目标账套连接 → 选择XLS并预览 → 点击导入 → 缓存必要档案并预检 → 完整单据数据校验及标记 → 源单号批量去重及标记 → 日期分组编号 → 完整单据批量事务及对账提交 → 统一结果并导出异常结果表。
2. 正常批次以5000～10000明细行作为可调软上限，不拆散一张单据；超大单据单独批次。正常路径不得退化为每行单独INSERT。
3. 每批同一连接、同一事务批量插表头，使用显式INSERT列清单及OUTPUT INSERTED.ExternalCode、ID、code回收映射，再批量插明细。不得按OUTPUT顺序配对，不假定executemany会返回所有结果集；驱动与临时表/OUTPUT组合必须先做集成验证。
4. 插入省略IDENTITY及rowversion/timestamp等系统生成列；不可写列依据实表元数据过滤。每个待写列明确定义来源、类型、精度、NULL和默认规则，不整行克隆218/207列CSV。
5. 对账通过后提交，只有commit确认成功才标记成功。一个表头及全部明细必须共同成功或共同回滚。
6. 批量数据错误先回滚当前整批，再按完整单据二分，子批分别开新事务；直到定位坏单，坏单标记失败，正常单据继续批量提交。回滚前ID映射作废，重试重新获取。
7. 死锁、暂时锁超时有限重试，不立即拆成坏单；权限、映射错误、日志空间等系统故障停止任务，保留已提交成功和未处理结果。
8. 断线或提交应答丢失时，先重连按ExternalCode查实际表头，再核对关联明细行数及逐单金额；确认完整才记成功，确认不存在才重试。结果不明或发现历史残缺时标记待确认，不盲目重插。

任务日志保存阶段、源单号、分配SA号、提交状态、表头ID和对账摘要。业务数据commit与日志落盘存在不同时成功的可能，以目标表查询恢复为准；日志不是唯一幂等依据。应用重启同样重新判重，不能依据“日志未成功”重复插入。

## 8. 统一结果与导出

覆盖全部源行：保留原始字段，新增任务ID、文件、工作表、物理行号、源单号、SA号、匹配档案ID、表头ID、状态、全部原因、原因行、失败阶段、SQLSTATE/错误码、金额差额和项目留空说明。

| 状态 | 含义 |
|---|---|
| 导入成功 | 整单校验通过且提交确认 |
| 重复跳过 | 主表已有相同源用友单号 |
| 校验失败 | 本行输入或必要关联不满足规则 |
| 整单受阻 | 同单其他行失败，整单不提交 |
| 写入失败 | 单据级数据错误已隔离且确认回滚 |
| 待确认 | 提交结果或已有数据完整性无法确认 |
| 未处理 | 系统故障等导致尚未处理 |

每行一个互斥最终状态，可以有多个原因和非阻断说明；项目留空说明不覆盖成功状态。输出成功、失败、跳过、待确认的单据数和行数，逐层核对总数。处理失败也落盘导出，导出失败单独报告并保留可恢复日志，不重新插入已提交数据。结果可导出XLSX/CSV；输入必须XLS不等于结果也必须旧式XLS。

## 12. PyQt主页面与六步操作流程（本轮新增）

本节依据用户最新操作描述，细化主页面和后台任务；与前文历史处理顺序冲突时，以本节“缓存—校验—去重—写入—导出”的顺序为准。本文只完善设计，不在本轮改动应用代码或执行SQL写入。

### 12.1 主页面读取配置并测试连接

主页面启动读取config中的SQL Server连接配置及目标账套，展示服务器、端口、登录用户、目标账套、配置加载状态及连接状态；密码只在内部使用，界面、日志及导出不显示明文。连接配置和目标账套冻结为本次任务的配置快照，贯穿测试、缓存、去重、写入和恢复查询。

“测试连接”在后台连接实际目标账套并执行只读探测，返回连接是否成功、实际DB_NAME及耗时。连接master成功不能显示目标账套可导入；必须实际连接显示的目标业务数据库。测试连接不写业务表，不触发缓存或导入。连接成功只证明当时可连接；固定档案、表结构及写入所需权限仍须在导入预检验证，不能以无意义试写数据检测权限。

失败时显示可读错误类别和脱敏信息，保留已加载文件。任何服务器、账号或账套变化使旧连接测试、缓存及预检结论失效；后续测试和导入必须使用新配置。业务日期、SA编号及默认规则不随界面显示改成机器日期。

主页面只读显示配置，不提供配置编辑、设置窗口修改或账套自由选择。用户手动修改唯一config文件，连接要素为SERVER（host及port）、DATABASE（db_name）、UID（user）、PWD（password）四部分。沿用当前INI结构时，对应[sqlserver]的ip、port、database、user、password五个键；SERVER由ip与port组合，不把这五个存储键误称五类连接要素。数据库名称即本次目标账套。

启动及点击“测试连接”时重新读取配置文件；读取成功后更新脱敏展示并使旧测试结论失效，再测试该配置。密码不明文显示。导入前核对文件中的配置是否与最近测试通过的快照一致；变化则拒绝启动本次导入并提示重新测试，不能悄悄切换账套。运行中使用冻结快照，外部修改文件不改变已启动任务；下一次测试/任务再读取新配置。缺键、非法端口或无法读取配置时明确报错，不回退另一份配置或另一个账套。

### 12.2 选择XLS并展示数据

点击“选择文件”选择与10.12A出.xls列结构一致的XLS，校验真实文件格式及必需列，后台读取全部有效工作表并记录来源。文件名无需固定为10.12A出.xls，列结构及业务语义须一致。多工作表或多文件的数据归集能力保留，文件选择框是否一次允许多选属于可扩展交互，首版可先支持单文件多工作表，不改变整单归集原则。

加载成功后在主页面表格显示源明细、源单号、来源位置及初始“待处理”状态，同时显示文件名、明细数和单据数。预览不自动查档案或写库。使用QTableView及表格模型，支持滚动、筛选和按单号查看，不为10万行创建大量单元格控件。显示分页或分段呈现不代表只导入当前页；“导入”处理全部已加载有效明细，不按选中行拆单。

预览只读，保留原值；校验、截断和匹配结果放在独立结果列，不覆盖原始数据。新文件读取失败不能留下混合的半新半旧任务；保留或恢复上一份有效预览并明确提示加载失败。读取成功替换当前输入并清空旧任务结果。空工作簿、缺列及无有效行都不给出“加载成功可导入”的状态。

### 12.3 点击导入：先缓存，再校验和标记

文件有效且当前目标账套测试通过后启用“导入”。点击后生成任务ID、冻结输入和配置，禁止重复点击导入、切换文件或更换账套；后台按第4节加载必要档案及固定配置，禁止按明细逐条查库。

随后解析、归集并校验所有单据。问题标记回传列表：行状态、问题字段、原值、原因和整单受阻关联。项目缺失为非阻断说明；客户、存货、仓库、单位、税率等必要关联失败则整单不写，健康单据继续。每行可以保存多个原因，不因先发现单位问题就丢掉税率问题。

主页面显示当前阶段、已处理/总行数、成功/失败/跳过单据数及可读进度；未知工作量用阶段状态，不伪造总完成百分比。缓存或结构/固定配置整体不可用时，进入任务异常并保留已知结果，不把全量未处理数据伪称逐行业务校验失败。

### 12.4 再按源用友单号去重并标记

完成数据校验后，对可识别源单号批量查SA_SaleDelivery.ExternalCode，并在列表标记重复跳过；此前收集的校验说明仍可查。目标已存在的源单号始终不新增，不因本次输入校验异常而失去去重保护。空/无效源单号无法判重，维持校验失败。

按最终互斥状态统计：已有源单号归“重复跳过”；非重复且不满足校验的单据归“校验失败/整单受阻”；通过者进入待写集合。说明标记不计成额外失败行，避免总行数重复计算。最终写入前保持同账套串行互斥，必要时再查重。

### 12.5 正常完整单据批量导入

校验及去重结束后自动继续健康单据的批量写入，不要求用户逐单确认；没有健康单据也正常进入结果输出。SA号只分配给待写入单据，主明细绑定数据库生成的ID。批次数据错误按完整单据二分隔离，其他健康单据继续，不因某一条明细出错留下孤立表头。

数据库连接在执行数据库操作的后台线程中创建及关闭，不跨线程共享cursor或连接。事务回滚和提交由工作线程管理，通过Qt信号批量发送进度及结果，主线程只更新模型。控制UI刷新频率，避免每行一个高成本信号令10万行任务卡顿。

提供“停止”按钮。点击后设置协作停止标志，不强杀工作线程：若正在写入，当前批次正常提交或因错误回滚后不再启动新批次，也不开始新的二分子批重试；已提交单据保留成功。因停止未执行的单据或已回滚而不再重试的单据标为未处理并说明停止原因，已知校验失败/重复结果继续保留。提交结果不明的单据仍标待确认，不能归为已回滚或未处理。

缓存、校验及去重阶段在安全检查点停止，不进入写入；已知结果保留，其余标记未处理。导出阶段是终止任务的一部分，点击停止不会丢弃结果或中断结果文件保存。界面显示“正在停止，等待当前操作结束”，数据库命令配置有限超时，不承诺点击即刻退出。运行中关闭窗口按同一停止流程等待结果保存，不直接关闭进程；强制关闭后的恢复仍按任务日志及源单号核实。

### 12.6 结束后导出标记数据

用户所称“导出失败表”在方案中统一称“异常结果表”：包含校验失败、整单受阻、写入失败、重复跳过、待确认、未处理等非成功行，以及导入成功但项目留空等需关注说明。名称和原因区分重复跳过、非阻断说明与实际失败，不把成功项目留空单据写成失败。

建议导出一个XLSX工作簿，分“汇总”“失败及未处理”“重复跳过”“成功但有说明”工作表；保留原始列、来源行号、源单号、最终状态及全部原因。原始数据和结果导出保持文本安全，文本内容不被当作公式执行。成功无说明的行留在任务结果及主页面，不进入异常明细；汇总仍包含全部输入和互斥状态计数。

导出触发于任务终止，无论全部成功、部分成功、全部校验失败或系统中止；不能要求先有成功写入才导出。运行级故障写入汇总原因并将未处理行准确标记。导出中不改业务状态，不因导出失败重复导入；保留结果并允许重试导出。关闭程序前的结果恢复依赖持久任务日志而非仅内存。

输出自动保存到当前导入文件所在文件夹；此处“应用输出目录”按用户指定落实为源文件父目录，不采用安装目录、进程工作目录或另一固定export_data目录。文件名采用“源文件名_账套_任务ID_异常结果.xlsx”，清理文件名非法字符且不覆盖原输入或已有结果。同一文件夹的其他文件不被读取为本任务输入。首版单文件多工作表的输出目录无歧义；未来若开放跨文件夹多选，须先确定输出目录规则，不自行任选某个文件夹。

生成文件先写同目录临时文件，成功关闭后再重命名成最终文件；保存失败不得显示导出成功。源文件夹不可写、磁盘不足或文件占用时明确报告“导出失败”，保留任务结果和恢复日志，提供重试及另存为，不改业务提交状态、不自动切换到未告知的位置。导入开始前检查输出目录可写性，无法写入时提示修复后重试，不先写入业务数据再发现输出位置不可用；执行期间出现的保存故障仍走结果恢复。没有标记行时只展示“无异常数据”及完整统计，不产生内容不明的失败文件；如需审计可另导出完整任务结果。
