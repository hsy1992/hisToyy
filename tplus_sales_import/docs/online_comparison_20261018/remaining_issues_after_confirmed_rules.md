# 已确认规则落地后的剩余问题

2026-10-18；本轮只读分析及离线模拟，没有修改应用源码或业务数据。

## 1. 确认存在的程序核验缺口

SqlRepository.verify_batch完整比较明细配置字段，但表头仅查询固定字段子集。未覆盖voucherdate、madedate、auditeddate、maker/makerid、auditor/auditorid、voucherState、币种、营销机构等。离线调用实际verify_batch，修改表头voucherState为0或makerid为999，函数仍返回True；修改新加入的DataSource或明细taxFlag则返回False。

建议：从build_payload的表头合同生成回查字段，排除确实由系统产生且不应精确比较的实际创建/更新时间；按字段类型统一日期与datetime比较，忽略仅小数位表达差异，业务字段逐项验证。提交前核验和断线提交恢复均使用同一合同。该发现证明检测能力不足，不表示本次实际数据已出现这些错误。

## 2. 新规则并不保证逐行复刻线上

对线上全部7566条记录，按源数据离线套用最新版规则（含税金额仍截断；未税金额四舍五入2位；单价按含税金额反算8位），与线上预测差异：含税金额281条、未税金额247条、税额34条、未税单价289条。字段计数重叠，不能相加。这是全线上源记录预测，不是本地现存数据的修复结果，也没有把本地缺档数据视为已经导入。

根因之一为含税金额仍保留用户原确认的截断规则，因此金额反算规则一致也不能使输入含税金额一致。线上7550条符合源金额HALF_UP，另16条例外，不能擅自统一改成HALF_UP或float规则。

另8条线上数量1、含税金额0、未税单价0.0001；本地新规则得到0，未授权设置最低单价。零数量退货与这一类不同，应继续保留，不能套用金额/数量公式。

## 3. 新版规则不会更新已有单据

去重逻辑仍直接跳过已存在ExternalCode。之前的金额、空taxFlag及旧isModifiedPrice等不会因重启/再次导入自动改变。若要修复存量，应先只读生成逐单旧值/新值预览与行数、金额影响，明确新导5166单与历史77单范围，再按单事务更新及核对；不得删单重导或自动覆盖。

## 4. 其他业务字段及流程仍有待验证

isCarriedForwardOut/In、refundDifferenceFlag、isPresent、isManualCost、agency/agencyid、auditedtime等尚未全部与线上对齐。NULL不当然等于0。审核相关字段写入不代表完整业务审核流程执行，须用T+界面验证打开、金额展示/重算、打印及状态。

成本、毛利、saleOutQuantity、docid及相关业务关联ID不能直接复制。不自动生成出库单、发票和凭证的既定要求继续有效。标记dataSource=2497和isSaleOut=15不应被当作已经产生对应业务单据的证明。

## 5. 档案与追溯

此前33单39行缺客户档案需补齐后重新校验；源单XKP0026202610122125客户编码空需修正源文件。两张零数量退货按现规则保留。

任务JSON、日志和输出还没有记录金额/默认标记规则版本，跨版本恢复和人工追溯容易混淆。建议持久化规则版本和新增字段合同，存量修复也记录版本；不将旧日志直接按当前规则重建后认定原写入错误。

## 推荐顺序

1. 补全表头字段核验（本轮已复现的检测缺口）。
2. 明确是否需要存量整改，先生成预览，不直接更新。
3. 决定含税金额是否继续按当前业务规则截断，8条零金额单价例外是否需要处理。
4. 补齐档案，验证T+业务状态和未配置标记。
5. 增加任务规则版本及分类对账输出。
